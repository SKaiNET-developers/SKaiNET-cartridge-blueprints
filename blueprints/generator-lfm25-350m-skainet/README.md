# LFM2.5-350M eager CPU cartridge blueprint

This source blueprint combines the repository's existing `llm/v1` profile with
SKaiNET-transformers' LFM2 model and text runtime. A POSIX shared library implements
Cartridge Runtime ABI 0.1 and keeps one private JVM worker alive between requests.
Inference executes on the eager CPU backend. The implemented target is Linux
AArch64 with external Java 21 and `jdk.incubator.vector`; there is no GPU or NPU
claim in this recipe.

The source tree includes no weights, compiled graphs, native libraries, acquired
license acceptance or signing keys. Build products remain private. The recipe's
`NOASSERTION` license marks pending package/dependency license remediation, even
though the source contribution follows this repository's MIT license. The
materializer output is an **unsigned diagnostic**, with no full conformance or
production-cartridge claim.

The adapter, persistent worker, native bridge and their tests now live once in
`:runtimes:lfm2-jvm` and are reused by the Vulkan source recipe. Earlier CPU target
qualification applies only to its captured source/JAR/pack closure. Rebuilding
this refactored distribution requires fresh target qualification; measurements
are never inherited from an earlier binary.

## Dependencies and tests

The model implementation belongs to SKaiNET-transformers, not this repository:

- `sk.ainet.transformers:skainet-transformers-inference-lfm2` supplies the model,
  checkpoint loader, state and CPU operations (`sk.ainet.models.lfm2`).
- `sk.ainet.transformers:skainet-transformers-runtime-klfm2` supplies the frontend,
  explicit decoder policy and text generator (`sk.ainet.apps.klfm2`).
- `:profiles:llm-v1` is the single profile contract used by the adapter and worker.

Until the new Transformers modules are released, use the independently reviewed
development checkout and preserve its source state for each evaluation. The optional composite
substitutes only those two modules; it does not include the evaluation workspace
or copy upstream API types. Once published, omit the checkout and select the
release with `-Plfm2TransformersVersion=<released-version>`.

From this repository's root:

```sh
./gradlew -Plfm2TransformersCheckout=/absolute/path/to/SKaiNET-transformers \
  :blueprints:generator-lfm25-350m-skainet:check \
  :blueprints:generator-lfm25-350m-skainet:installDist
```

`check` runs JVM adapter/worker tests, a one-Default-worker backpressure regression,
synthetic packaging/consumer/benchmark-validator tests, and source-built native
bridge tests with a fake worker. It requires Python 3 and a C++17 compiler on a
POSIX host, but no checkpoint, target device or model download. A normal repository
`build` includes these tests through its existing lifecycle aggregator.

The three small golden transcripts preserve previously recorded exact HF prompt
IDs, output IDs and text, with original evidence hashes in the fixture. They are
bounded reference-fidelity checks. The multiturn answer `3` is incorrect in the
model and reference; matching it is not evidence of task quality.

## Prepare exact execution artifacts

Acquire the publisher's seven pinned files for
`LiquidAI/LFM2.5-350M@9e6c6ccf47cd318696e137d381a7ded8fe4df09f`
in a private directory. The recipe verifies the weights and all six metadata
files, including `LICENSE`, before supplying a local file mirror to the actual
blueprint fetcher. Use of the restricted model remains subject to its publisher's
license; no acceptance is generated by the recipe.

Build the Linux ARM64 compiler image from SKaiNET-IREE-tools at its pinned 3.11.0
toolchain, or select an already available compatible image with
`-PnativeCompilerImage=<image>`. The native build helper verifies the image's
platform and embedded version, captures its immutable image ID, then runs that
exact image with networking disabled. It uses clang to compile the POSIX bridge;
IREE does not execute inference in this CPU recipe.

```sh
./gradlew -Plfm2TransformersCheckout=/absolute/path/to/SKaiNET-transformers \
  -Plfm2ModelDir=/private/pinned/checkpoint -PnativeRun=001 \
  :blueprints:generator-lfm25-350m-skainet:prepareNativeExecution
```

The output is `build/runs/001/execution` under this blueprint directory. It contains
the real native library, actual worker JARs, verified model files, worker config
and frozen short-chat workload. `execution.json` records the recomputable file
closure. `manifest.json` is explicit unsigned **staging metadata**, not a valid
signed cartridge manifest. Model files use verified hardlinks where possible.
Preparation executes no inference. Nonmodel artifacts are independent copies, so
a later compiler or installDist cannot change the staged JARs.

`preparePreviewProfile` and `resolveNativeDescriptors` use the actual plugin
resolver to freeze both canonical ABI bytes and the exact pretty descriptor bytes
the final materializer will write. The preview's stable performance fields name
the target class and workload path only; a separate marker says it is unmeasured.
Both byte sequences are embedded in the library. Numeric measurements stay in
the later benchmark report, avoiding a descriptor rebuild after measurement.

## Measure, accept and materialize

Transport the execution directory to a Linux AArch64 target. If the model already
exists there, omit `artifacts/model` from transport, copy `scripts/prepare.py`, and
reconstruct exactly with local pinned files:

```sh
python3 prepare.py stage --execution /private/upload/execution \
  --model-dir /private/pinned/checkpoint --output /private/new-run/pack
```

The external Java installation is never copied or linked into the pack. Set
`JAVA_HOME` on the target. Copy the two benchmark/consumer scripts next to each
other and run:

```sh
export JAVA_HOME=/private/java-21-home
python3 benchmark_native_cartridge.py --pack /private/new-run/pack \
  --library /private/new-run/pack/artifacts/runtime/liblfm2_cartridge.so \
  --workload /private/new-run/pack/artifacts/evaluation/native-abi-workload.json \
  --output /private/new-run/benchmark --timeout-seconds 1800
```

The workload uses one loaded cartridge, three warmups and thirty fresh sessions.
It saves raw native-call timestamps, stream events, process identities, sampled
RSS and external-JRE identities. Its supervisor bounds the owned process group
and preserves partial evidence on failure. This is application latency for a
fixed short-prompt mix, not steady-state throughput or task-quality qualification.

Return the complete benchmark directory to the build host:

```sh
./gradlew -Plfm2TransformersCheckout=/absolute/path/to/SKaiNET-transformers \
  -Plfm2ModelDir=/private/pinned/checkpoint -PnativeRun=001 \
  -PusePreparedNativeExecution=true \
  -PnativeBenchmarkDir=/private/returned/benchmark \
  :blueprints:generator-lfm25-350m-skainet:verifyMaterializedExecution
```

Prepared-artifact mode consumes the frozen execution directory and avoids rebuilding
its dependencies while separate development continues. The directory must already
exist and match the complete benchmark inventory.

That task chain independently validates raw evidence and current source/artifact
identity, derives an accepted private profile, invokes the actual unmodified
materializer and checks every copied execution and evidence byte. It does not
reuse timing numbers from a different build. The descriptor and native runtime
remain byte-identical to the measured execution. The final manifest additionally
records benchmark evidence and materialization provenance.

The final pack lives at
`build/runs/001/materialized/generator-lfm25-350m-skainet-linux-aarch64`.
Run `consume_native_cartridge.py --pack PACK --library LIB --requests REQUEST_DIR
--output NEW_JSON` on that final target pack, then validate the returned report
with `scripts/validate_native_cartridge.py`. This separate functional gate checks
the three exact references, invalid requests, lifecycle, ownership and in-flight
cancellation. It is not `ctg-conform`.

Every attempted output directory is exclusive. Retain failed or completed runs
and use a fresh `nativeRun` when inputs change. The guard prevents the upstream
materializer from deleting an earlier pack. This recipe owns its generated
preview/accepted profiles and does not consume another blueprint's root
`-Pprofile` or signing key configuration.

## Boundaries

Only greedy text messages are supported: no tools, structured-output mode or
multimodal input. The context limit is 2048 tokens; the worker defaults to 32 and
caps requested output at 256. One generation is active per cartridge. Decoding
uses explicit `HUGGING_FACE_5_COMPAT` policy; the source checkpoint's own decoding
policy remains separately available in the Transformers API.

An upstream relocation changes JAR/native identities and therefore needs fresh
target execution and measurement. Historical evaluation results are not copied
onto this build. Full GPU generation, long-context behavior, source/dependency
license remediation, builder-owned signing, independent signature verification,
full conformance and a production external-JRE policy remain separate gates.
